# Core Pull Request Dispatcher Strategy

- **Status:** Accepted
- **Date:** 2026-08-15
- **Immediate implementation:** `OMG.PSUtilities.Core`
- **Long-term owner:** `OMG.PSUtilities` meta-module

## Decision

Keep `Approve-PSUPullRequest` and `Complete-PSUPullRequest` in Core for the immediate patch,
but treat every provider-specific command as optional. Resolve the selected command with
`Get-Command` before invoking it and throw actionable guidance when it is unavailable.

Do not add `OMG.PSUtilities.AzureDevOps` to Core's `RequiredModules`. AzureDevOps already
requires Core, so the reverse dependency would create this cycle:

```text
OMG.PSUtilities.Core -> OMG.PSUtilities.AzureDevOps -> OMG.PSUtilities.Core
```

## Immediate Contract

The Phase 5 Core patch must:

1. Preserve the two existing neutral public command names and parameters.
2. Detect GitHub and Azure DevOps only from a valid `origin` remote.
3. Resolve the selected provider command before invocation:
   - GitHub approval: `Approve-PSUGithubPullRequest` from Core.
   - GitHub completion: `Complete-PSUGithubPullRequest` from Core.
   - Azure DevOps approval: `Approve-PSUADOPullRequest` from AzureDevOps.
   - Azure DevOps completion: `Complete-PSUADOPullRequest` from AzureDevOps.
4. When a GitHub command is missing, direct the user to update or reinstall
   `OMG.PSUtilities.Core`.
5. When an Azure DevOps command is missing, direct the user to install or import
   `OMG.PSUtilities.AzureDevOps`.
6. Reject a missing remote or unsupported provider before attempting provider dispatch.
7. Never install a module, mutate `PSModulePath`, or change repository state implicitly.

Tests must cover both providers, each missing-command path, a missing `origin`, and an
unsupported remote. No path may surface `CommandNotFoundException`.

## Evidence

- `OMG.PSUtilities.AzureDevOps.psd1` declares
  `RequiredModules = @('OMG.PSUtilities.Core')`.
- `OMG.PSUtilities.Core.psd1` requires only `ImportExcel` and exports both neutral
  dispatchers.
- Both Core dispatchers currently invoke AzureDevOps commands directly without first
  resolving them.
- `Approve-PSUGithubPullRequest` exists in tracked Core source, while
  `Complete-PSUGithubPullRequest` is referenced but absent from tracked Core source.
- Generated artifacts contain a completion implementation and optional-command guards, but
  generated output is not the source of truth and must not be copied without the Phase 0.4
  branch/provenance audit.
- The meta-module already requires both Core and AzureDevOps and therefore can own neutral
  dispatch without adding another dependency edge.

## Long-Term Placement

Move the neutral dispatch implementation to the existing `OMG.PSUtilities` meta-module in a
future compatibility release. Do not create another provider-neutral module for two commands.

The migration order is:

1. Ship the guarded Core patch without changing public names.
2. Add equivalent tested commands to the meta-module in a later minor release.
3. Deprecate the Core copies with guidance to import the meta-module.
4. Remove the Core copies only in a documented breaking release.

During migration, the dependency graph remains acyclic:

```text
OMG.PSUtilities
|-- OMG.PSUtilities.Core
`-- OMG.PSUtilities.AzureDevOps -> OMG.PSUtilities.Core
```

## Rejected Alternatives

- **Add AzureDevOps to Core's `RequiredModules`:** rejected because it creates a cycle and
  forces AzureDevOps onto GitHub-only Core users.
- **Leave unguarded calls:** rejected because optional-provider absence becomes a raw
  `CommandNotFoundException`.
- **Create a new neutral module now:** rejected because the meta-module already provides the
  required aggregation boundary.
