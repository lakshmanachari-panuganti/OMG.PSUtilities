# Token Issuer Contract Decision

- **Status:** Accepted - fail closed
- **Date:** 2026-08-15
- **Applies to:** `OMG.PSUtilities.AI/Private/New-PSUApiKey.ps1`
- **Endpoint:** `POST https://omg-gemini.azurewebsites.net/api/issuetoken`

## Decision

Disable the free-token path until the service has a named owner and returns a documented,
data-only response. The client must never execute `HeaderScript` or any other text received
from the service.

When a safe service contract is available, the client may construct its authorization headers
locally from these required fields:

```json
{
  "authorization": "Bearer <token>",
  "clientUsername": "<name>",
  "clientDevice": "<device>",
  "clientIp": "<address>",
  "expiresOn": "2026-08-16T00:00:00Z"
}
```

The client must reject a response when:

- any required field is absent or empty;
- `authorization` is not a non-empty Bearer value;
- `expiresOn` is not a valid future UTC timestamp; or
- the response contains `HeaderScript` or another executable-content field.

The response and authorization value must not be written to verbose, debug, error, or host
output.

## Evidence

A live response was captured on 2026-08-15 at 03:54:57 UTC. No response values or executable
text were retained or executed. The response exposed these properties:

| Property | Runtime type |
| --- | --- |
| `apiKey` | `System.String` |
| `startDate` | `System.DateTime` |
| `endDate` | `System.DateTime` |
| `id` | `System.String` |
| `HeaderScript` | `System.String` |

The `HeaderScript` sample parsed without syntax errors but was not data-only:

- length: 2,177 characters;
- SHA256: `7e57bae454dd7274e22bb0263cc1d37343afce62a6b2b0fb9c15389278182878`;
- command invocations: `Get-CimInstance`, `Get-PSUPublicIP`;
- assignment targets: `device`, `deviceid`, `Script:headers`, `username`;
- generated header keys: `Authorization`, `psu-clientdevice`, `psu-clientid`,
  `psu-clientip`, `psu-clientusername`, `psu-signature`.

This disproves the assumption that the endpoint only returns a benign header assignment.

## Ownership And Source

The service owner and implementation source are unverified:

- Azure Resource Graph found no matching `Microsoft.Web/sites` resource across all four
  subscriptions available to the authenticated account.
- GitHub code search across `lakshmanachari-panuganti` found only this client integration and
  its tests, not the endpoint implementation.
- DNS resolves the host through Azure App Service infrastructure, but DNS does not establish
  resource ownership.
- Commit `7fea88ce4a17a41d9c403ca1a016403b6381234b` introduced the current client URL; that proves
  client provenance, not service ownership.

A named service owner and source repository are prerequisites for re-enabling this path.

## Rollout

1. Keep the free-token path disabled with an actionable error.
2. Assign a service owner and identify the endpoint source repository.
3. Deploy and document the data-only response contract.
4. Add client tests for valid data, missing/malformed fields, expiry, executable-content
   rejection, and secret-free output.
5. Update `New-PSUApiKey` to parse the response and construct headers locally.
6. Release the service before or atomically with the updated client.

## Consequences

- The free AI tier is unavailable until the service contract is corrected.
- Explicit user-supplied credentials remain the supported path.
- Module 4.1 can remove `Invoke-Expression` without preserving an unsafe compatibility mode.
